## Local development

1. Create a new repository based on the `aem-block-collection` template and add a mountpoint in the `fstab.yaml`
1. Add the [AEM Code Sync GitHub App](https://github.com/apps/aem-code-sync) to the repository
1. Install the [AEM CLI](https://github.com/adobe/helix-cli): `npm install -g @adobe/aem-cli`
1. Start AEM Proxy: `aem up` (opens your browser at `http://localhost:3000`)
1. Open the `{repo}` directory in your favorite IDE and start coding :)

## Content import (migration)

Imported content lives in `content/*.plain.html` and is generated by the importer in `tools/importer/`.

**Always import via the wrapper npm scripts** — they run the bulk import **and then automatically strip leaked comments** from the generated content:

```sh
npm run import:home      # imports the homepage (en)
npm run import:career    # imports the career/company/solutions pages
# generic form for any template:
npm run import -- --import-script tools/importer/import-<template>.bundle.js --urls tools/importer/urls-<template>.txt
```

Why the wrapper matters: the source is a Lit/web-component SPA, so the bulk-import serializer re-emits empty `<!---->` and `<!--?lit$…$-->` comment markers into the content **after** transformers/parsers run. Left in place, the xwalk conversion (`md2jcr`) fails with *"Element 'html' is currently not supported."* The wrapper's post-step (`tools/importer/strip-leaked-comments.mjs`) removes those markers while preserving the `<!-- field:… -->` hints that md2jcr relies on.

- If you ran the raw bulk importer directly, clean the output afterwards with: `npm run clean:content`
- The bulk-import script path defaults to the marketplace location; override it with the `EXCAT_BULK_IMPORT` environment variable if it lives elsewhere.

### Block models & component configuration

The root `component-definition.json`, `component-models.json`, and `component-filters.json` are generated from the `models/` and `blocks/*/_*.json` sources via `npm run build:json`. A husky pre-commit hook runs this automatically whenever a model partial (`_*.json`) is staged and re-stages the regenerated config, so the two never drift. If you edit a block model outside of a commit, run `npm run build:json` manually to keep the config in sync (stale config causes *"Component configuration not found in workspace"* during conversion).
